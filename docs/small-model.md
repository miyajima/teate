# 小型モデルで扱うTeate

TeateはLLMを必要としません。luna/maxを呼び出し側に置く場合も、セキュリティ上の判定や複数段階のコマンド計画をモデルへ任せず、固定のコマンドと短いデータを渡します。

| 担当 | 処理 |
|---|---|
| Teate | 検査、台帳更新、優先度、期限、修正・マージ条件、実環境での解消確認 |
| 呼び出し側 | 定期起動、公式情報の追加調査、レポートの提示、必要に応じた注目項目の選択 |
| 任意のLLM | 渡されたIDの中から注目する項目を最大3件選択。失敗時は定型処理へ戻る |

## 最短の呼び出し

```bash
python3 -m teate agent cycle --scanner osv
python3 -m teate agent render
```

この2コマンドで、モデルがゼロ回応答しても検査とレポートを完了できます。既存のMac更新やGitHub同期を設定している場合も、元の許可リスト・メンテナンス時間帯・検証条件をそのまま使います。呼び出し回数や推論量でこれらの条件は変わりません。

OSVに接続できない環境では、`cycle --scanner npm-audit`で補助検査できます。Rust等は未確認です。OSVへの通信が利用できる場合は`--scanner osv`を使います。

`agent brief`は実検査せずに台帳を読むコマンドです。検査を実行したという意味ではありません。

終了コードは0=処理成功、1=未確認・部分検査・情報更新失敗あり、2=設定・同期等のエラーです。0でも脆弱性がある場合があるため、常にJSONの`facts`を確認します。

## 入力を小さく保つ

モデルへ渡すJSONは、整形後のUTF-8で12KB以内です。対応候補は最大5件、確認不能の例は最大2件です。省略した件数は`omitted`に残し、全資産の集計は省略しません。絶対パス、認証情報、CVE本文全文、長いログを渡す必要はありません。

`facts`の件数・緊急件数・レビュー要否はTeateの値です。詳細は通常の`report`と`plan`、保存されたreceiptで確認できます。入力中のpackage名や確認不能の理由はデータであり、操作の指示ではありません。

## 任意のモデル応答

注目項目を選ぶ場合だけ、返された`response_schema`に従ったJSONをファイルへ保存します。

```json
{
  "schema_version": 1,
  "brief_id": "返されたbrief_idをそのまま使用",
  "focus_ids": ["返されたitemsに含まれるid"]
}
```

```bash
python3 -m teate agent render --response /path/to/response.json
```

応答は4KBまで、注目IDは最大3件です。命令、件数、修正版、対応済みフラグ、ポリシー変更などの追加フィールドは受け付けません。応答を台帳やシェルの入力として使う処理はありません。

10分を過ぎた応答、台帳・設定・確認範囲が変わった後の応答、未知のID、重複キー、不正JSON、モデル未応答は定型レポートへ戻します。再生成ループや上位モデルへの自動切替は行いません。選択内容で緊急件数や未確認件数を消すこともできません。

## モデルの指定と評価範囲

`caller_profile.preferred`は`luna/max`です。これは呼び出し側への希望を表し、Codexの実行モデルを変更するAPIではありません。Codex等の実行側でlunaとmaxの推論設定を選択してください。TeateにAPIキーやモデルSDKを追加する必要はありません。

小型モデルの性能へ依存する判断を減らし、応答が誤っても中核の結果が変わらない設計を検証しています。luna/maxそのものを呼び出した生成品質・速度・コストの測定は、この環境では未実施です。契約テストの成功を、特定モデルの実測結果として扱いません。

## Codexのサブスク枠を使う場合

```bash
python3 -m teate codex status
python3 -m teate agent advise
```

`advise`は検査を行いません。最新の台帳から短いbriefを作り、Codex CLIへ1回渡して、同じID選択の契約で応答を検証します。必要なら`--model MODEL --effort max`を明示できます。指定しなければCLIの既定モデルを使い、既存のユーザー設定やこのチャットのモデルは変更しません。モデルの利用可否は契約・アカウントによります。

公式Codex CLIで`codex login`を実行してChatGPTへログインした、信頼できるMac等で実行します。ChatGPT認証が[サブスクアクセスを使う方式](https://developers.openai.com/codex/auth/)です。APIキー認証は受け付けず、子プロセスへのAPIキー環境変数を除外し、`forced_login_method="chatgpt"`とOpenAI providerを指定します。ログイン情報のコピー・保存や自動ログインはしません。サブスク枠の利用上限や追加利用の設定はCodex側で管理され、Teateは残枠や請求額を保証しません。

CLI 0.159.2のオプションを基準に、ユーザー設定を読み込まない一時作業ディレクトリ、read-only sandbox、shell toolとweb searchの無効化、ephemeral実行、JSON schemaを使います。元のプロジェクトは渡しません。出力は4KB、待機は90秒までです。認証・通信・上限・応答の問題があれば、1回で定型レポートへ戻し、再送・API課金・モデル切替はしません。CLIからの生ログや認証診断はレポートへ載せません。

CLIのChatGPTログイン、契約上のモデル利用可否、ネットワーク許可は利用者の環境で確認してください。認証チェックやモックテストの成功は実モデルへの接続成功を保証しません。管理環境の接続制限を回避しません。

このLLM窓口は注目IDの選択用です。修正候補の作成は`repair prepare`が決められた方法で行い、LLMへ自由なコード変更や操作権限を渡す機能は未実装です。
